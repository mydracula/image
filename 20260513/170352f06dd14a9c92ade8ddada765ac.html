"工厂已经实现过黑灯工厂——全程无人值守。但办公室白领工作从来没有实现过这一点。" 张韶峰在访谈中反复强调。在他看来，Open Agent 这类长任务 Agent 的出现，第一次让坐办公室的白领/灰领有了对标"黑灯工厂"的可能——"很多工作可能干三四天，根本不需要人干预"。

张韶峰把过去两年的"震撼时刻"精确地切成两段。第一次是 2025 年初 DeepSeek 破圈，它让"AI"这个词第一次真正地渗透进传统企业主的日常。第二次则是 OpenAI 的 Open Agent——因为它是中国企业主第一次看到"一个 AI 可以帮我完成一条长任务链"。

我的一位同学，生产中高端起重机，45% 销售都销往海外。他说："我很想做 AI，但我该从哪里起步？我甚至应该找我们公司什么人来负责都不知道。但我又知道说 AI 时代已经来了，我不做有一天会被淘汰。" —— 张韶峰 · 转述同学的焦虑（真实原话）

这位做起重机的同学代表了几乎所有传统企业主。张韶峰描述他们的状态："既振奋又焦虑"——振奋是"AI 可以让我多赚钱或省成本"，焦虑是"我看到有的企业用 AI 出了大问题"。整期访谈的核心动机就是：**给这位同学一个真实可操作的答案。**

02

百融内部 · 硅碳员工体系全解

人格化 · 父母分离 · 北极星

百融智能内部有一套被投资人反复问起的系统，叫 "硅基员工之家"。它把所有 Agent 当作"员工"来管理——每一个 Agent 都有姓名、工号、邮箱、绩效、入职日期、父亲、母亲，以及对外收发邮件的完整人格接口。这不是营销话术，这是一套真刀真枪的管理机制。

03

三个坑 — 百融踩出来的教训

人性 · 流程 · API

张韶峰毫不掩饰地列出了百融踩过的三个坑。这些坑不是技术问题，而是**人性和制度**。任何想做 AI 落地的企业都会碰到。

  • 忽略员工为什么要配合 光讲"这是趋势"没用。落地好不好，取决于微观层面的人性。必须把硅基员工的绩效算进真人员工的考评——让"教 AI 的人"从中多拿钱。
  • 上来就想改流程 流程变 = 利益格局变。应当先不改流程，只把每个个人能力从 1 放大到 10。有了信任和数据之后，再动格局。
  • 没打通传统 SaaS/软件层 软件会变成被 Agent 调用的工具。所有传统软件必须暴露 API（或 MCP / CLI）。2024 年 Function Call 能力变强后，这条路才真正通了。

访谈里张韶峰还原了一个时间点：2023 年时大模型的 Function Call 还很弱，那时候"改造 CRM、订单系统让它被 Agent 调用"根本做不到。直到 2024 年 Function Call 能力突然变强，这条路才跑通。这也解释了为什么今天我们看到"MCP"成为热词——它本质上是 Function Call 路径的标准化。

更深层的教训是人性的奖惩设计。百融最早推的时候忽略了这一点，结果是下面推不动。后来明确"业务负责人的绩效与 AI 替身挂钩"之后，员工反过来主动调 Agent——因为他的 AI 替身干得越好，他自己的季度奖金越高。这就把"我为什么要帮一个会替代我的东西变强"这个死锁彻底反转。

中国 SaaS 长期失败 — 根因与破局

按结果付费 · 快递小哥模式
◆ 一个残酷数字 中国整个软件产业营收 只有美国的 4%——但中国 GDP 是美国的 2/3。严重不成比例。张韶峰认为：这是 10 年之内唯一一次翻身机会。

◢ 百融从第一天就没按传统 SaaS 走

2014 年公司成立时，张韶峰对同事说的原话："我们不要去做传统软件模式，我一定不要去做。" 这句话让百融在接下来的 10 年里走出了一条完全不同的路。

A

替代人力定价

三年平均水平员工 / 月工作量的 3 倍，客户只付 5,000 元/月。ROI 4-6 倍。

B

计件 / 计时

按审批次数、按小时。完成一件工作收一次钱——"快递小哥模式"。

C

按交易分成

促成交易 → 抽 10-20%。连电话网络费都是乙方出。甲方零前置成本。

哪怕你前期收入高，你不可持续。你明年就没了。 —— 张韶峰 · 对定制化项目的判决

张韶峰对传统软件格局的态度是"非常悲观"——已固化、不可改。但他对智能体产业充满乐观：甲方付费习惯和乙方收费模式还没有固化。这是可以重塑整个产业商业模式的窗口期。

他的呼吁是"所有传统软件企业要合作改变这个产业的现状"。不要再去做 20-50 万的定制化项目——这是把 AI Agent 的伟大机会重新拽回软件公司那套失败模式的死亡之路。从甲方的角度"按结果付费"、从乙方的角度"规模化可复用的 Agent"是唯一出路。

05

Agent 已落地的两大场景

程序员 · CCC · PMF
第一大场景

程序员

  • ✅ 可闭环：输入 → 代码 → 编译 → 测试
  • ✅ 可衡量：覆盖率、bug 数、交付速度
  • ✅ 用户愿意用：程序员是 AI 原住民
  • ✅ 强化学习闭环持续提升
&
第二大场景

CCC · 联络中心

  • ✅ 不用见面，纯语音/文字
  • ✅ 像真人一样交互，99.9% 听不出
  • ✅ 价值好衡量：满意度 95% + 完成件数
  • ✅ 美国对标：Sierra、Decagon

张韶峰把 Agent 第一大场景定义得毫无悬念——程序员。不是因为"程序员最需要"，而是因为程序员的工作天然符合 AI 学习和迭代的条件：可闭环、可衡量、用户愿意用。三者缺一不可。这也解释了为什么 Cursor、Claude Code 等能跑通，而"给普通白领做一个 Copilot"常常失败。

第二大场景是 CCC（Contact Center，联络中心）。这是全世界公认已经找到 PMF 的场景。它之所以能跑通，是因为：不用见面（纯语音/文字即可）、拟人化交互技术已经过关（99.9% 客户听不出）、企业本来就有外包计价习惯（按满意度 + 完成件数算）。百融直接切入——以前给 BPO 付 100 万的活，百融收 50 万干两倍，ROI = 4 倍。

◆ 三个支撑条件缺一不可 一个场景要在今天做 Agent 成功，必须同时具备：① 可闭环 · 有明确的输入输出边界；② 可衡量 · 结果好坏能被数据判定；③ 用户愿意用 · 使用者不抵触。任何一条缺失都会导致项目卡住。这是评估你自己业务场景是否可落地 Agent 的快速 checklist。
06

AI Roll-up — 收购 BPO 再 AI 化

红杉 · 80 倍市场 · 不裁员

AI Roll-up 是过去一年 ToB 圈最热的概念之一。逻辑是：收购传统 BPO（业务流程外包）公司 → 用 AI 替换里面的人力 → 同样的人接 10 倍的活 → 利润爆炸性增长。 百融是中国第一个吃螃蟹的企业。

这是百融式 Roll-up 哲学的关键——不以降本增效为直接目的。直接目的是"把规模做到原来的 10 倍"，员工数变化是副作用而不是目的。这个哲学让百融在收购 BPO 时比单纯追求裁员的 PE 更有说服力：被收购公司的员工不会天天担心失业，反而愿意配合 AI 化。

08

自研 vs 外采 — 模型取舍

专属大模型 · 三个判据

张韶峰对模型层的取舍极其实用："我们优先使用专属大模型——为这个领域优化过的。往往是自建。"

1

通用模型不够逼真

例如语音合成的方言、口音、拟人度——通用模型达不到"人味"，客户一听就觉得是机器。百融需要音色克隆 + 方言合成。

2

通用模型成本太贵

"我没办法做一单亏一单。"客户给百融付的钱不够覆盖通用 API 的调用成本——自建模型才能让单位经济成立。

3

基础设施不具备

做全球化需要低延迟——如果服务器只在北京，新疆时延就撑不住。这些都不是纯粹的 AI 问题，而是系统工程问题。

自建覆盖两层：Pre-training（预训练）+ Post-training（后训练，含 fine-tuning）。百融不做基础 LLM 的全量预训练，但在特定垂直（如金融语音、金融审批）上做了大量 post-training。

四条建议 · ACTIONABLE ADVICE

给焦虑一号位的处方

整场访谈最可复用的四条——张韶峰给 FOMO 中一号位的忠告，浓缩为一句话：观念升级 · 别想太易 · 人性设计 · 从可衡量高频入手。

09

四条建议 — 给焦虑一号位

观念 · 期望 · 人性 · 起点
  • 观念升级 · AI 是平齐的工作伙伴 很多企业家把 AI 当工具，这个观念要升级。AI 可以是工具，但越来越多它是和你"平齐的工作伙伴"——它干的工作和你的工作是对等的。这次不是互联网那种"流通侧"变革，这是生产侧革命。
  • 不要把这事想得太容易 DeepSeek 开源、Open Agent 开源 ≠ 免费可用。如果误以为 AI = 插即用 → 真用起来发现难 → 觉得是忽悠 → 挫败信心 → 真正启动可能推迟 2-3 年 → 错过窗口。
  • 人性设计 · 激发善抑制恶 把奖惩机制设进去——让"会教 AI 的人"从中受益（父亲角色拿到绩效），让"承担转型"的部门不会被视为"在挖自己的坟"。善良被激发 → 才能自下而上把 Agent 用起来。
  • 从简单高频可衡量的入手 不要追求大而全高大上。先从客服 / 营销 / 合同 / 报销起步——输入输出清晰、高频见效、结果可量化。有了小胜利 → 员工觉得靠谱 → 老板看到 ROI → 持续投资 → 正反馈。
10

最顶层判断 · 生产侧 vs 流通侧

ToB · ToC · 合流

这是整场访谈最抽象、但也最顶层的判断——把过去 200 年几次大技术革命串成一条轴线。张韶峰的核心论断是：最高等级的革命，首先是从供给侧弊端开始，然后再延伸到 C 端。

◢ 历次大技术革命的共同规律

  • 蒸汽机供给侧 / 生产侧起步 → 后延伸至物流与消费
  • 电力革命供给侧起步 → 后扩散至家用电器
  • 计算机（IBM 大机）ToB 起步（企业用）→ 后下沉至 PC 和个人
  • 互联网 / 移动互联网本质是"流通/消费侧" → ToC 受益远大于 ToB
  • 这次 AIToB · 办公室白领起步 → 未来延伸到具身智能 / 制造业
每次最高等级的革命，首先是从供给侧弊端开始，然后再延伸到 C 端。因为需求虽然会拉动供给，但如果供给没有革命性改变，需求拉到一定程度产出不了了。 —— 张韶峰 · 历史级判断
◆ 历史性可能 中美历史上第一次真正意义上 ToB 科技公司的商业模式、产品、资本观点合流。以前：中国 ToB 软件 / ToC 差距 > 10 倍。这一次：ToB 企业直接受益于生产力革命，有可能追平 ToC。这是整个访谈对产业长期走向最乐观的一个判断。
11

八大可检验命题

可反驳 · 可指导决策
1
黑灯办公室命题

Open Agent 第一次让办公室白领有了对标"黑灯工厂"的可能——这是区别于互联网时代工具性变革的质变。

2
硅碳员工命题

Agent 不是工具，是"平齐的工作伙伴"——需要姓名、邮箱、父母、绩效、奖惩。它是一种新的"员工类别"而非一件软件。

3
人性先于技术命题

上来就改流程必败。先不动利益格局，把个人能力 1 放大到 10。利益格局变动必须在"既得利益者先受益"之后。

4
按结果付费命题

中国 SaaS 失败的根因是"过程性/工具性"难收费；AI 时代的出路是按结果付费 / 快递小哥模式——完成一件收一次钱。

5
窗口期命题

传统软件格局已固化、不可改。但 Agent 产业的甲乙付费习惯还没固化——这是 10 年一次的翻身机会。

6
AI Roll-up 命题

所有 BPO（含咨询/律所/会计）都是可 AI 化的目标；目的不是裁员，而是让同样的人接 10 倍的活。

7
专业服务下沉命题

跨国 firm 的护城河是"跨国专家"——智能体已经打破这个壁垒，专业服务将从大 firm 下沉到"个体 + AI"。

8
生产侧革命命题（最顶层）

过去 30 年互联网 / 移动互联网是"流通侧"；这次 AI 是"生产侧"——ToB 第一次有机会在产品/资本上与 ToC 合流。

12

一张可执行的 Checklist

8 步 · 逐阶推进
01
观念升级

AI = 平齐工作伙伴，不是工具。内部统一话术，避免把 AI 项目降级为"IT 工具采购"。

02
期望校准

不把事情想太简单。先用小样本项目跑出坑 → 再承诺 ROI → 避免"过山车式"信心崩塌。

03
人性先行

设计奖惩：教 Agent 的人拿绩效加成；AI 替身业绩 = 真人业绩。激发善意，抑制恶意。

04
场景挑选

客服 / 营销 / 合同 / 报销 · 高频 · 可衡量 · 用户愿意用。避开一开始就改业务流程。

05
不改流程先增能

把个人能力从 1 放大到 10。第一阶段不动利益格局，只让每个员工"变超级员工"。

06
建立硅碳比指标

作为北极星。部门级考核：任务被硅基 Agent 完成的比例。持续上升 = 转型健康。

07
打通传统软件

SaaS / CRM / 订单系统全部暴露 API（或 MCP）。让 Agent 可调用，让存量系统不至于"断层"。

08
商业层重构

从"按坐席 / 按人天"转为"按结果付费"。这决定了 5 年后谁还活着、谁已经消失。

“ToB 和 ToC · 历史性合流”

这一次很有可能是中美历史上第一次，ToB 科技公司的商业模式、产品、资本观点合流。
—— 张韶峰
